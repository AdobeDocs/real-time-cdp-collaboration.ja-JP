# 広告露出のソーシング用に[!DNL Google Cloud Storage]を設定

[!DNL Google Cloud Storage] （GCS） バケットをAdobe Real-Time CDP Collaborationに接続して、広告露出（広告ログ）データを収集し、測定します。

Real-Time CDP Collaborationの測定モジュールは、広告主のコンバージョンデータとメディア企業の広告露出ログを結びつけ、プライバシー重視のキャンペーンレポートを提供します。 これにより、広告主とパブリッシャー向けに、セルフサービスのノーコードパスが追加されます。 [!DNL Google Cloud Storage]に既に保持している広告露出（インプレッション）ログを、Adobe Experience Platformに依存することなく、Measurement for attributionに取り込むことができます。 バケットを接続し、検出されたデータが広告ログスキーマに一致することを確認します。測定は数分で終了します。

接続時にデータが引き出されません。 測定レポートを実行すると、ソーシングがトリガーされます。 ストレージを最小限に抑えるために、Adobeは7日間の保存期間の後、ソースされた広告ログを自動的に削除します。

[!DNL Google Cloud Storage]から取得した広告ログのガバナンスとデータ処理ルールが、Adobe Experience Platformから取得したデータに適用されるルールと一致しています。

>[!NOTE]
>
>このガイドでは、広告主とパブリッシャー&#x200B;**広告ログ** （広告露出）をクラウドストレージからソーシングする方法について説明します。 クラウドストレージからのコンバージョンデータのソーシングは、近日開始されます。

## 前提条件 {#prerequisites}

設定ワークフローを開始する前に、このセクションのすべての項目を完了してください。 このガイドに従う前に、[&#x200B; アカウントのオンボーディングと設定](./onboard-account.md)を完了している必要があります。

### GCSのアクセスと権限 {#gcs-access-permissions}

ウィザードを開始する前に、AdobeにGCS バケットへの読み取り専用アクセス権を付与する必要があります。 [!DNL Google Cloud]詳細な手順については、[Google Cloud Storage権限の設定](#setup-gcs-permissions)を参照してください。


### 広告ログデータの準備 {#prepare-adlog-data}

ソーシングを開始する前に、広告ログファイルが[広告ログスキーマ &#x200B;](#ad-log-schema)に準拠している必要があります。 主な要件は次の通りです。

* **ファイル形式：** CSVのみ。
* **正規列ヘッダー：** ファイルは、[広告ログスキーマ &#x200B;](#ad-log-schema)で定義された正規列ヘッダーを使用する必要があります。 このバージョンでは、列ごとのリマッピングや自動スキーママッピングはサポートされていません。
* **必須フィールド：**&#x200B;すべての必須フィールドと、少なくとも1つの一致キーが存在する必要があります。
* **一致するキーハッシュ：**&#x200B;一致するキーハッシュ値は、小文字の16進数SHA-256にする必要があります。
* **列の一貫性：**&#x200B;設定したパスのすべてのファイルで、同じ列レイアウトを共有する必要があります。
* **サブフォルダー：** ファイルは、指定されたパスに直接配置する必要があります。 Collaborationはサブフォルダーをトラバースしません。

   ![新しいデータ接続を追加を選択した状態で、データ接続の選択ステップを示す測定データの追加ワークフロー。](../../assets/setup/gcs-adlog-sourcing/add-new-data-connection.png){zoomable="yes"}

4. 新しいデータ接続のデータソースを選択：**[!UICONTROL Google Cloud Storage]**。 「**[!UICONTROL 次へ]**」を選択します。

   ![Google Cloud Storage、Google Blob Storage、Azure Data Lake Storage Gen 2のオプションとAzure Cloud Storageを選択した状態で、データソースの選択手順を示す測定データの追加ワークフロー。](../../assets/setup/gcs-adlog-sourcing/gcs-adlog-source-selection.png){zoomable="yes"}

5. 「**[!UICONTROL データ接続を追加]**」ウィザードが開きます。 **[!UICONTROL Connect Google Cloud Storage]** ステップで、広告ログファイルが存在する&#x200B;**[!UICONTROL バケット]**&#x200B;と&#x200B;**[!UICONTROL パス]**&#x200B;を指定します。 両方のフィールドは必須であり、設定されたパスにあるすべてのファイルは1つのデータセットとして扱われます。

   ![Connect Google Cloud Storage ステップのAdd Data Connection ウィザード。必須のバケットとパス フィールドが表示されます。](../../assets/setup/gcs-adlog-sourcing/gcs-adlog-connection-details.png){zoomable="yes"}

6. **[!UICONTROL 名前と説明]** ステップで、データ接続に必要な&#x200B;**[!UICONTROL データ接続名]**&#x200B;とオプションの&#x200B;**[!UICONTROL 説明]**&#x200B;を指定します。

   ![名前と説明の手順。データ接続名と説明フィールドが表示されます。](../../assets/setup/gcs-adlog-sourcing/gcs-adlog-name-description.png){zoomable="yes"}

7. **[!UICONTROL フィールドをマッピング]**&#x200B;手順で、検出された列をプレビューして、ウィザードが正しいファイルを読み取ることを確認し、次に[広告ログスキーマ &#x200B;](#ad-log-schema)を確認します。このスキーマには、すべてのフィールド Measurementが理解でき、必須フィールドとオプションフィールドの比較、検出された列がID/照合キーとして認識されるフィールドが一覧表示されます。 この手順は読み取り専用の検証です。システムは、必須ヘッダーが存在することを確認し、必須フィールドがない場合はブロックします。 このバージョンでは、列ごとのリマッピングはありません。

   ![検出された列のプレビューと広告ログ スキーマのレビューを表示するフィールドのマップ手順。](../../assets/setup/gcs-adlog-sourcing/gcs-adlog-map-fields.png){zoomable="yes"}

## 広告ログソーシングの仕組み {#how-it-works}

[!DNL Google Cloud Storage]からの広告ログのソーシングは、オーディエンスのソーシングに使用される高レベルのフローを反映します。

1. **クラウドストレージ接続：**&#x200B;は、広告ログを保持するバケットへの読み取り専用アクセスを設定します。
2. **スキーマのレビューと検証：** システムは、広告ログスキーマ（フォルダー、ファイル、必須ヘッダーチェック、読み取り専用）に対してファイルを検証します。
3. **フィールドマッピング：**&#x200B;のソース ID フィールドは、正規の列名に基づいて、正規フィールドに自動的にマッピングされます。 手動リマッピングはありません。
4. **取り込みおよび正規化：** イベントは、露出ごとに1行に正規化されます。 測定レポートを実行すると、広告ログのソーシングが開始されます。

### 広告ログスキーマ（標準的なCSV形式） {#ad-log-schema}

必須フィールドが存在する必要があります。また、次の表の&#x200B;**結合キー（必須フィールドの1つ）**&#x200B;とマークされたフィールドも少なくとも1つ存在する必要があります。 一致するキーハッシュ値は、小文字の16進数SHA-256です。

| フィールド | データタイプ | 必須 | 説明 |
| --- | --- | --- | --- |
| `EVENT_DATETIME` | 文字列（ISO 8601） | 必須 | イベントのタイムスタンプ |
| `EVENT_ID` | 文字列 | オプション | イベントの一意のID |
| `EVENT_TYPE` | 文字列（列挙） | 必須 | イベントの種類： `{impression, click}`の1つ |
| `HASHED_EMAIL_SHA_256` | 文字列（64文字16進数） | 結合キー（1つ以上が必要） | メールの小文字の16進数SHA-256 |
| `HASHED_IPV4_SHA_256` | 文字列（64文字16進数） | 結合キー（1つ以上が必要） | IPv4の16進小文字SHA-256 |
| `DEVICE_ID` | 文字列（64文字16進数） | 結合キー（1つ以上が必要） | デバイス広告ID |
| `DEVICE_ID_TYPE` | 文字列（列挙） | オプション | `{idfa, gaid, aaid, rida, afai, msai, vida, lgudid, tifa}`の1つ |
| `ECID` | 文字列（64文字16進数） | 結合キー（1つ以上が必要） | Demdex ベースのECID |
| `CUSTOM_ID` | 文字列 | オプション | パブリッシャー/パートナーの永続的ID （PPID、RampID、Core IDなど） |
| `ADVERTISER_ID` | 文字列 | 必須 | 広告主の一意のID |
| `ADVERTISER_NAME` | 文字列 | オプション | 広告主/ブランド名 |
| `CAMPAIGN_ID` | 文字列 | 必須 | プラットフォーム固有のキャンペーン識別子 |
| `CAMPAIGN_NAME` | 文字列 | オプション | 人間が判読できるキャンペーン名 |
| `PLACEMENT_ID` | 文字列 | 必須 | プレースメントの一意のID |
| `PLACEMENT_NAME` | 文字列 | オプション | わかりやすいプレースメント名 |
| `CREATIVE_ID` | 文字列 | オプション | 広告クリエイティブの一意のID |
| `CREATIVE_NAME` | 文字列 | オプション | 人間が判読できるクリエイティブ名 |
| `AUDIENCE_ID` | 文字列 | オプション | オーディエンスセグメント ID |
| `AUDIENCE_NAME` | 文字列 | オプション | 人間が読めるオーディエンス名 |
| `DEVICE_TYPE` | 文字列（列挙） | オプション | `{mobile, desktop, tablet, ctv, dooh, car, in_store, other}`の1つ |
| `AD_FORMAT` | 文字列（列挙） | オプション | `{display, video, native, audio, search, commerce, dooh, other}`の1つ |
| `SITE_NAME` | 文字列 | オプション | インプレッションが発生したネットワーク/サイト/アプリ/発行者プロパティ |
| `TEST_GROUP` | 文字列 | オプション | リフト調査、テスト/コントロール、ホールドアウトグループのグループ化 |
| `CUSTOM_DIM` | 文字列 | オプション | 追加のパブリッシャーディメンション |

{style="table-layout:auto"}

>[!NOTE]
>
>`MATCH_KEY_TYPE`はスキーマのオプション フィールドとして含まれているため、時間の経過とともに複数のID タイプを並行してサポートし、一致キーの出所（メール、電話、またはCRM）をv1契約を解除することなく保持できます。

### 検証要件（v1） {#validation-requirements}

設定ワークフローを完了する前に、システムがソースデータを検証およびログに記録します。 検証チェック：

* ソースフォルダーには、少なくとも1つのファイルを含める必要があります。
* ファイルを空にすることはできません。
* 必須スキーマヘッダーが存在する必要があります。
* オプションのスキーマフィールドは省略できます。
* 必須フィールドのみを含むファイルは有効です。

検証エラーにより続行できません。 システムは、データ型、フィールド値、レコードの完全性、データ品質、自動スキーママッピングを&#x200B;**not**&#x200B;検証しません。 検証は、この最初のリリースのフォルダー、ファイル、および必須ヘッダーのチェックに限定されます。

## 既知の制限事項 {#known-limitations}

[!DNL Google Cloud Storage]広告ログのソーシングを設定および使用する場合は、次の制約に注意してください。

* **広告ログのみ：**&#x200B;この接続は、広告主または発行者の広告ログ （広告露出）をソースにします。 コンバージョンデータはまだサポートされていません。
* **サポートされているソース：** [!DNL Google Cloud Storage]および[!DNL Azure Data Lake Storage]または[!DNL Azure Blob Storage]。
* **ファイル形式：** CSVのみ。
* **正規ヘッダーが必要です：**&#x200B;このバージョンでは、列ごとのリマッピングおよびインテリジェント/自動マッピングはありません。 ファイルは正規の列名を使用する必要があります。
* **値/型の検証がありません：**&#x200B;必須の列ヘッダーのみが検証されます。 最初は、データ行がない可能性があります。
* **作成後に接続を編集しません：** アクティブな照合キーの変更を含め、変更を加えるには、新しい接続を作成する必要があります。
* **パスごとに1つのレイアウト：** パス内のすべてのファイルは、1つの同一の列レイアウトを共有する必要があります。 レイアウトが混在すると、部分的なソーシングの失敗が発生する可能性があります。
* **トラバースされないサブフォルダー：** ファイルは、指定されたパスに直接配置する必要があります。
* **設定でスケジュールまたは振り返りがありません：**&#x200B;測定レポートを実行すると、広告ログのソーシングが開始されます。 レポートを設定する際の振り返り期間を設定します。
* **1つの広告ログデータ接続：**&#x200B;一度に1つの広告ログデータ接続のみを設定します。 測定レポートは、設定された接続を自動的に使用します。

## トラブルシューティング {#troubleshooting}

* **接続に保留中のデータが表示されます/ データがありません：**&#x200B;これは、最初の測定レポートが実行されるまで想定されます。 接続時にデータはソースされません。
* **「データが見つかりません」がソース手順：** フォルダーが空です。 続行する前にファイルを追加してください。
* **プレビューに列が表示されません：** ファイルは存在しますが、空です（ヘッダーまたはコンテンツはありません）。
* **過去の検証を取得できません：**&#x200B;必要な列ヘッダーがありません。 必須フィールドを確認し、正規名を使用して、少なくとも1つの一致キーが存在することを確認します。
* **認識できない列：**&#x200B;正規以外の列名は、既知のフィールドとして取得されません。 これらの名前を正規形式に変更します。このバージョンでは再マッピングは行われません。
* **セットアップ後にソーシングが失敗しました：** Adobeのバケットへの読み取りアクセス権が変更されておらず、ファイルが設定されたパスに正規形式で残っていることを確認します。
* **レポートの日付範囲が完全にカバーされていない：** 7日間の自動データ有効期限を覚えておいてください。 7日を超えるログは、要求された範囲では利用できない場合があります。

## [!DNL Google Cloud Storage]権限の設定 {#setup-gcs-permissions}

AdobeがGCS バケットから読み取ることを許可するには、次の権限を持つカスタム IAM ロールを作成します。

| 権限 | 目的 |
| ------------- | --------------- |
| `storage.buckets.get` | バケットのメタデータの読み取り： |
| `storage.objects.get` | オブジェクトデータとメタデータの読み取り： |
| `storage.objects.list` | バケット内のオブジェクトのリストを表示します。 |

{style="table-layout:auto"}

このカスタムロールを、お住まいの地域（NA、EMEA、またはオーストラリア）のAdobe Google サービスアカウントに付与します。 この設定を完了するには、**Google Cloud Account Admin**&#x200B;権限が必要です。

## アップグレードまたは移行に関する考慮事項 {#upgrade-migration}

* 以前にExperience PlatformまたはAdobeを使用した設定でオンボーディングしたお客様は、セルフサービスのクラウドストレージパスに移行できます。 既存の測定レポートとフローは変更されません。
* オーディエンスソーシングと同様に、広告ログファイルに存在する照合キーをCollaboration アカウントに対して有効にする必要があります。
* ガバナンスとデータ処理のルールは、Experience Platformから取得したデータと一致します。

## 次の手順 {#next-steps}

ソーシングが完了すると、広告ログを測定レポートに使用できるようになります。

その他の広告露出のソーシング方法については、[広告露出のソーシング用にAzure ストレージを設定](./configure-azure-adlog-sourcing.md)を参照してください。
